## v1.0.10 — 修复：同名不同版本被判成同一首而跳过

### 修复
- **歌单/「我喜欢」命名改用接口 `title`（带版本标记）而不是 `name`（裸名）**。
  实测「我喜欢」355 首：按 `name` 命名撞名 **11 组**，按 `title` 命名 **0 组**。
  例：`周深、王者荣耀 - 我们在场 (和声伴奏).flac` 与 `周深、王者荣耀 - 我们在场.flac`
  是两个不同版本（mid 不同、`name` 相同、时长都是 200s），旧版会把后一首直接 SKIP 丢歌。
- **每个下载文件写入歌曲指纹标签 `qqmusic_songmid=<歌曲 mid>`**
  （flac/mp3 自定义帧、m4a 用 `use_metadata_tags`、opus 落在 stream 标签；wav 容器不支持 → 退回 PCM 比对）。
- **跳过判定前移到下载之前**：重跑时先读指纹，命中同一首直接 SKIP，一个字节都不下
  （旧版是整首下完再判断，355 首重跑等于白下约 14GB）。
- 同名但指纹不同的另一版本 → 自动另存 `xxx (2).flac`，绝不互相覆盖；序号码文件同样参与指纹匹配。
- 老文件（本版本之前下载、没有指纹标签）：文件名唯一时沿用旧行为直接 SKIP；文件名有歧义时
  下载后比对**解码 PCM 的 MD5** 确证，同一首则**自动补写指纹**（下次零流量跳过），不同则另存序号。

### 打包 / CI
- 新增 GitHub Actions `release.yml`：推 `v*` tag 自动双端 PyInstaller 打包（内置 ffmpeg/ffprobe）、
  跑内置自测（含 ffmpeg 相关用例）、生成 `SHA256SUMS.txt` 并上传到 draft Release。
- macOS 打包脚本改为自动定位 ffmpeg（`QQMUSIC_FFMPEG` → `PATH` → Homebrew 默认路径）。

### 资产
| 文件 | 说明 |
|---|---|
| qqmusic-decrypt-macos-arm64.zip | macOS arm64 单文件 + 文档 + `Start-Mac.command` |
| qqmusic-decrypt-win64.zip | Windows x64 单文件 exe + 文档 |
| SHA256SUMS.txt | 上述两个 zip 的 SHA256（CI 生成，与资产同源） |

macOS 首次运行：解压后双击 `Start-Mac.command`（或 `xattr -dr com.apple.quarantine <解压目录> && chmod +x qqmusic-decrypt-mac`）。
Windows：解压后直接运行 `qqmusic-decrypt-win.exe`（内置 ffmpeg/ffprobe，无需另装）。
